# Prototype v0.1：C3 时间文本联调协议

此协议由 A+B 合并实现，配套 `firmware/esp32-c3/main/main.ino` 和 Android App 0.4.0；包含 TIME1 校时扩展。
当前固件仅在按键时生成原始时间文本，上电和重连不生成记录；它不等于 `data-format.md` 的正式事件协议。
团队已确认“一条有效按键时间记录＝一次用药记录”。App 0.4.0 保留 `prototype_text.db` 原文，并将每个唯一的 `device_id + file_id` 写入 `records_device.db` 的 `timestamp_uses` 表，供概览、历史、CSV 和助手统计使用。此映射不改变线协议，也不冒充传感器测量；压力、时长、置信度、电量和原始时区均不补造。

有效时间以 Unix 秒（UTC）为准，范围为 2001-01-01 ～ 2099-12-31；设备无校时（2000 年占位）作为未知时间保留，未知与未来时间不计入按日次数。设备只保存并传输 UTC 秒；手机收到后加上手机当前系统时区偏移换算为本地时间显示，设备不感知时区。重传不重复计次，同秒不同文件分别计次，同一文件内容冲突则停止同步。启动时自动补录全部历史原文（不限最近 100 条），先原文持久化、再日记持久化、最后 ACK；中途退出可通过重传或启动补录修复。收到 DONE 后才更新统计库的最后同步时间。

## GATT 与组帧

Service：`4fafc201-1fb5-459e-8fcc-c5c9c331914b`。
Characteristic：`beb5483e-36e1-4688-b7f5-ea07361b26a8`，Read / Write With Response / Notify，CCCD `0x2902`。

每次 Notify 最多 20 字节，不依赖 MTU 协商。App 按字节缓存到 LF 再解码 UTF-8，最大一行 256 字节。
固件通知格式为 `LF + body + "|" + crc4 + LF`。前置 LF 能使重传从残缺帧恢复；空行忽略。
CRC-16/CCITT-FALSE：poly `0x1021`、init `0xffff`、refin/refout=false、xorout=0，覆盖 body 的 UTF-8 字节，不含末尾分隔符、校验值或 LF。crc4 为四位十六进制。独立标准校验向量 `123456789 → 29b1`。
App 发出的控制命令不带 LF，单次 Write With Response，最多 20 字节。

配套固件必须来自 `codex/android-xiaozhi-prep`，当前旧 `main` 没有 HELLO/READY。C3 / Arduino-ESP32 3.3.11 使用 NimBLE，实际订阅以 `onSubscribe` 的 Notify 位为准；`BLE2902::getNotifications()` 在该栈仅表示特征能力，不能用作客户端已订阅的证据。固件连接时保留 Notify 能力、重置订阅状态，收到 HELLO 后等待订阅，再发 READY。

`token` 为设备每轮生成的 8 位十六进制会话标识（设备发起 `REQ`）。设备 ID 为 12 位 eFuse 芯片标识（与手机系统给出的连接 ID 分开）。`index` 为本轮快照的零起始序号，不是正式事件序号。

| 方向 | body / 控制命令 | 行为 |
|---|---|---|
| App → 设备 | `HELLO` | 先建立 Notify 订阅，再发送；每秒重试，最多 6 次 |
| 设备 → App | `READY\|device_id\|P01\|TIME1` | CCCD 已启用且 App 校验成功后开始校时；旧 P01 三字段 READY 仍可同步，但明确标注不支持校时 |
| App → 设备 | `TIME\|utc_hex16` | 仅传 UTC：Unix 秒数为 16 位十六进制（64 位无符号）。不传时区偏移；设备始终以 UTC 走时 |
| 设备 → App | `TIME_OK\|utc_hex16` | 系统时钟设置及 NVS 保存成功后原样确认；仍使用分片、换行及 CRC，匹配本次请求后 App 才自动同步 |
| 设备 → App | `TIME_ERR\|reason` | `BAD_TIME`、`BUSY` 或 `CLOCK_STORAGE`；App 停止自动同步，允许手动重试校时 |
| 设备 → App | `REQ\|token\|count` | **设备主动**发起传输请求：连接校时完成后，以及每次按键记录后（已连接且已订阅时）。`token` 为设备本轮生成的 8 位十六进制会话标识，`count` 为设备已扫描到的待传文件数；最多 256 个 |
| App → 设备 | `SYNC_REQ\|token` | **同意**设备的 `REQ`，原样回传同一 `token`；取消旧轮次 |
| 设备 → App | `BEGIN\|token\|count` | 收到匹配 `SYNC_REQ` 后固定本轮文件总数；最多 256 个 |
| App → 设备 | `START\|token` | 已校验 BEGIN，可以发送第一条 |
| 设备 → App | `R\|token\|index\|file_id\|raw_text` | raw_text 为 16 位十六进制 UTC Unix 秒（64 位）；file_id 不含目录前缀 |
| App → 设备 | `ACK\|token\|index` | 必须在 CRC 校验、字段检查及 SQLite 事务成功后发送；相同文件相同内容可以重发 ACK |
| 设备 → App | `END\|token\|count` | 本轮所有记录均已获 ACK |
| App → 设备 | `COMMIT\|token` | 已保存完整连续快照；确认本轮文件可归档，设备将其移入 DA/DB 归档区 |
| 设备 → App | `DONE\|token` | 归档完成后才发；App 收到才显示本轮完成；重复 COMMIT 返回相同 DONE |
| 设备 → App | `ERROR\|token\|reason` | 显示设备错误，本轮停止，不清空文件 |

## 重试与数据保留

- 校时只接受 UTC Unix 秒（2001～2099）。App 每 2 秒重试同一命令，共最多 3 次；同一连接内固件对相同命令只设一次时钟，再次收到仅重发 TIME_OK，避免重试把时钟调回过去。
- 新固件每次连接先校时，校时成功后由**设备主动**发 `REQ|token|count`，App 回 `SYNC_REQ|token` 才开始同步。手动“校准设备时间”完成后设备同样重新发 `REQ`。同步期间不校时。旧 P01 固件继续原同步路径；旧 APK 不识别 TIME1，升级时应同时更新固件与 APK。
- **按键触发**：每次按键记录写入 SPIFFS 后，如果已连接且已订阅，设备立即发 `REQ` 请求新一轮传输；否则记为待同步，等下次握手完成或下次连接后补发一次 `REQ`，保证按键记录不会无人认领。
- REQ、BEGIN、R、END 均等待相应应用层回复；固件 1.5 秒超时重试，最多额外 3 次。超过次数发 `ACK_TIMEOUT`，保留文件。
- App 接收期间 12 秒无有效进展报超时；等待 DONE 时每 2 秒重发 COMMIT，最多额外 3 次。
- 坏 CRC 不 ACK，等待设备重发。序号不连续、文件内容冲突、存储失败均停止本轮，不 COMMIT。
- 同设备 `device_id + file_id` 是原型数据库主键；重传不增加数据，同键不同内容拒绝覆盖。
- **COMMIT 后归档**：设备把本轮实际传输的文件改名进 DA/DB 归档区（`data_<hex>_<n>.txt` → `DA_<hex>_<k>.txt` 或 `DB_<hex>_<k>.txt`，`k` 为组内 1～50 序号，hex 为原 UTC 秒）。归档只按“本轮传输了哪些”，不按时间先后。归档区永不传输。
- **两组滚动**：当前组满 50 个后切到另一组；若目标组已有整代文件，先整组删除再从 1 重新计数。因此设备最多保留两代归档，更旧的一代即使从未同步也会被删除（团队已确认此取舍）。当前组与序号存 NVS，重启后继续。
- **传输范围**：`collectFiles` 只收 `data_*`，`DA_*`/`DB_*` 一律跳过；因此不会重传已归档文件，也不会因归档触发重复计数。
- 断线时清除当前会话，自动重连最多 3 次；用户主动断开/取消扫描会取消延迟重连。重连后设备重新发 `REQ`，同步全部未归档的 `data_` 文件，手机去重；这不是正式协议的游标续传。
- 新文件增加 Preferences 持久计数，防止同秒按键及重启后手动时钟重复造成覆盖。旧原型 `.txt` 仍可读取。
- 发送、断线和归档都不调用 `SPIFFS.format()`；归档只用 `SPIFFS.rename()`，回收旧代只用 `SPIFFS.remove()`。挂载使用 `SPIFFS.begin(false)`（首次上机可由硬件组手动初始化一次）；挂载失败报告错误。
- 快照期间新增的按钮记录留在 `data_`，下一轮传输。归档上限为两代共 100 个文件，加上未归档的 `data_`，设备占用有界；单轮仍设 256 个文件上限，超过报告 `TOO_MANY_FILES`。

## 时钟与浅睡眠

- 系统时钟存 UTC，设备不保存时区。原始文件内容与文件名均使用 16 位十六进制 UTC Unix 秒；手机显示时加手机当前系统时区偏移。之后手机时区改变，显示随之变化，无需重校。已有文件不被改写。
- NVS 原子保存 UTC 快照。浅睡眠期间 RTC 继续走时；冷启动恢复的是最后已知时间，无法补回断电期间经过的时间，必须再次连接手机校准。首次无快照时使用明确的 2000 年占位，串口提示 `CLOCK_UNCALIBRATED`；校时前按键记录只能作为原型诊断，不能当作准确记录。
- 无连接且无同步、按键或待处理命令，空闲 30 秒后关闭 BLE 并进入浅睡眠。按 GPIO4 按钮唤醒，保留这次按键记录，再恢复广播；睡眠中的设备无法由手机蓝牙连接唤醒。
- Arduino-ESP32 3.3.11 的 BLEService 没有公共析构入口；为避免反复重建 GATT 泄漏，唤醒先写入本次按键记录并保存当前时钟，然后软件重启恢复广播。上电路径不产生额外记录，SPIFFS/NVS 编号不清空；重连后手机再次校时。睡眠 API 失败也回到软件重启路径，不卡在睡眠循环。连接或同步期间不主动睡眠。

## 当前边界

手机校时不证明发生真实服药，也不修正历史文件。DA/DB 归档仅保留两代设备侧副本，不是备份：手机数据库损坏时无法从设备重新取回已归档的旧数据。正式 20 字节事件协议、传感器事件识别及正式游标待继续开发；四特征 GATT 不会与本单特征原型混用。浅睡眠的唤醒、重复 BLE 重启及耗电表现需由硬件组在实际板上验收。
