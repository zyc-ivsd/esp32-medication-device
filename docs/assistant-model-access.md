# 本地专家 / 联网大模型：App 侧的模型接入与边界

本文记录“本地规则助手 ⇄ 联网大模型”这条链路的架构、**API Key 的边界**，以及 RAG、朗读（TTS）的落地方式。

本地助手是确定性的规则程序，读取手机中的记录统计，不包含模型权重或手机端大模型推理。在线助手才调用用户配置的模型服务；填写的模型名称由请求原样传给该服务，App 不会自行替换它。

### 长回复的接收与中断处理（2026-10-03）

App 0.3.1 将回答正文（UTF-8 256 KiB）、整段 JSON（2 MiB）、SSE 传输总量（16 MiB）和单行 SSE（1 MiB）分开限制，替代原来统一的 64 KiB 限制。SSE 每段会重复元数据，所以传输量不能当作正文字数。建连、响应头以及连续没有网络数据的等待上限为 120 秒；接收持续输出时不限制总时长，心跳和思考数据也会重置网络空闲计时。

客户端取消会关闭连接；网络超时、接收超限或上游出错时保留已经收到的正文并标记未完成。`finish_reason=length` 等非正常停止原因即使伴随 `[DONE]` 也不能当成完整回答。部分回答的状态随聊天记录保存在手机中，不参与下一轮上下文、不自动朗读；明确的中断给重试入口。服务商的输出额度和上下文限制仍由服务商控制，客户端不会通过自动重试增加 API 消耗。协议依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。

回归测试使用本机 HTTP/SSE 服务覆盖超过旧限制的长正文和协议流量、输出截断、网络心跳、真实空闲超时，以及部分回答的保留和历史过滤；测试不使用真实 API Key、不产生模型账单。

> **当前结论（2026-09-30）：放弃小智路线，在线只保留 BYOK 直连。** API Key 只能是**用户自己的**，**加密保存在手机**（`flutter_secure_storage`），调用时直接发送给所选模型服务、不经过团队服务器；团队/共享 Key、自建网关 `xiaozhi` / `llm` 上游只作历史保留，不再作为 forward 路径。下面各节里提到网关/小智的地方都按这个口径读。

## 一、用户看到的两级开关

| 级别 | 入口 | 联网 | 需要什么凭据 |
|---|---|---|---|
| **本地专家** | 助手页顶部「本地 / 在线」分段控件选 `本地` | ❌ | 无 |
| ~~在线：团队网关~~（历史） | 无入口（新增/编辑表单已移除；仅遗留档案只读） | ✅（历史） | 网关地址 + 网关访问码 |
| **在线：我自己的模型** | 分段控件选 `在线`（或右上角齿轮 → 管理 API） | ✅ | 模型服务地址 + 用户自己的 API Key + 模型名 |

两种在线方式里，**只有「我自己的模型」（BYOK 直连）是 forward 路径**；团队网关连同它背后的 `xiaozhi` / `llm` 上游已废弃，代码留作历史、不再推荐部署。本地/在线可随时互切，切换只追加分隔提示、**不再清空对话**；在线时输入框上方常驻一条提示，写明每次提问实际发出去的是什么。

**切换是一步操作**：配置过 API 之后，点分段控件里的「在线」直接切过去（用管理页里选中的那条），不再弹设置页；没有配置过才打开管理页引导。回本地永远是一步。

表单不再提供「测试连接」按钮：保存前只在本地用 `toProvider()` 试构造一次，地址或 Key 不完整就地报错，不发任何网络请求——直连的真实调用会消耗用户额度，不能拿它当连通性测试。

## 二、两类 Key，规则不同（重要）

仓库原有规则写的是“API Key 必须保存在网关，不得进入 App”。这条针对的是**团队的 / 共享的 Key**。用户自带 Key（BYOK）是另一类东西，必须分开表述：

| | 团队的 Key | 用户自己的 Key（BYOK） |
|---|---|---|
| 存放位置 | 只在服务端环境变量 | 用户手机上：内存 + 系统安全存储（见第五节） |
| 能否在 App 里输入 | ❌ 绝对不行 | ✅ 运行时输入 |
| 能否进源码 / 构建参数 / 仓库 | ❌ | ❌ **同样禁止** |
| 是否经过团队服务器 | 由它自己承载 | ❌ 直连模型，不经过我们 |
| 泄露后果 | 团队账号被盗用、可能产生账单 | 仅该用户自己受影响 |

**结论：“App 里能输入 API Key” ≠ “可以把 Key 打包进 App”。后者依然绝对禁止。** 团队/共享 Key 路线已废弃：现在没有“让用户的 Key 经过团队服务器”的 forward 场景。

## 三、为什么放弃小智

`xinnan-tech/xiaozhi-esp32-server` 的大模型配置是**服务端级**的：模型配置存在服务端、按智能体绑定，请求里**没有**传用户凭据的入口。所以：

| 想要的 | 智控台能给吗 |
|---|---|
| 角色设定、知识库 RAG | ✅ |
| **团队配置的**大模型 | ✅ |
| **每个用户用各自的 Key** | ❌ **不能** |

小智路线的本质是“一个管理员配好的 agent 给所有用户共用”，Key 归服务器、记忆也共享——这和“API Key 只加密保存在用户手机、不经过团队服务器”的目标直接冲突，所以**放弃小智**。要 BYOK，只能由 App 自己的代码调模型，也就是 App 直连（`DirectLlmAssistantProvider`，**已实现**）。

## 四、RAG：设备端关键词检索（已实现）

“检索必须在有知识库的那一方执行”在 BYOK-only 下只有一种解法：**知识库放手机里、检索在手机上做**，命中片段随“问题 + 摘要”一起发给用户自己的 provider。这样 Key 加密保存在手机、只直接发给用户自己的模型服务，检索本身也全离线。

| 方案 | 检索在哪 | 生成用谁的 Key | Key 是否经过团队服务器 | 结论 |
|---|---|---|---|---|
| 网关做检索 / 网关生成 | 团队网关 | 团队的或透传 | ✅ 经过 | **废弃**（与 BYOK 冲突） |
| 自建小智 + 智控台 RAGFlow | 小智服务端 | 服务端固定的团队 Key | 不适用 | **废弃** |
| **设备端关键词检索** | 手机内 | 用户的 | ❌ 不经过 | **已实现** |

实现是 [`assistant_knowledge.dart`](../mobile_app/lib/assistant/assistant_knowledge.dart)：语料是二十几篇自包含片段（设备边界、错误码、时间/同步、维护、隐私、术语、App 功能），用关键词匹配打分取 top-3，**没有 embedding / 向量模型**——这个小语料用不上，也能保持“零新依赖、全离线”。检索命中时才往 user 消息里加一个 `references` 字段；没命中就还是只发“问题 + 摘要”。

匹配在归一化（小写化、去掉空白与中英文标点）之后做，分三档：**同义组**（「服用」也能命中关键词是「吃药」的篇章）、**字面子串**、以及够长关键词的**字符二元组近形匹配**（容忍一两个错别字，例如「同步失贝」仍能带回「同步失败怎么办」），命中标题再额外加分。这样“近7天 / 近 7 天”“BLE / ble”“同步失败 / 同步失贝”都能命中，而不需要为每个变体写死一份关键词。

**语料只放“这个设备和这个 App 自己才知道、通用模型答不了”的事实**，明确**不放**药品说明书、剂量表、用药指导、疾病说明——那些会诱导医疗建议（见 `server/assistant-gateway/knowledge/README.md` 的收录原则）。通用健康问答（“介绍一下哮喘”）由模型自己的知识 + `【来源】AI知识` 标记处理，不走 RAG。

“App 功能”这一类就是为此加的：让助手熟悉整个 App 的用法（导入/导出、清空对话、搜索、朗读、大字、切换在线），在线模式问「怎么清空对话」也能检索到对应片段作为依据。它们只讲设备与 App 用法，**不含任何医学内容**（有测试守卫），不会诱导医疗建议。

## 五、多份 API 与管理页

用户说的「一个 API」在这份代码里叫一条**档案**（`AssistantProfile`）：一个名字 + 对应的地址与凭据。**新增/编辑表单现在只产出「我自己的模型」（直连）这一种**——它才是 forward 路径；`gateway` 模式与网关本身连同它背后的 `xiaozhi` / `llm` 上游已废弃，只作遗留档案的只读历史保留，表单里不再提供。

**管理页**（`assistant_api_console.dart`，右上角齿轮 / 未配置时点「在线」）列出全部档案，每条可以做四件事：**查看**（名字、模式、发到哪、凭据掩码）、**使用**（切到在线并记住它是选中的那条）、**编辑**、**删除**（二次确认）。底部「添加新的 API」打开表单。

**表单**（`assistant_settings_dialog.dart`）只负责收集字段，返回一条档案，不接触存储；落盘全部由管理页统一完成。两条刻意的设计：

- **保存即落盘，删除即清除。** 点「保存」就写入 [`flutter_secure_storage`](../mobile_app/lib/assistant/assistant_credentials.dart)（Android Keystore / iOS Keychain），**绝不用 `shared_preferences` 明文存储**；控制权交给「删除」——这也是本页唯一需要用户主动记住的隐私操作。
- **写不进去就报错。** 安全存储写入失败时管理页显示错误并且**不改动界面**，不会让用户以为「已经保存了」或「已经删掉了」——两种误解都有隐私代价。存储整体读不出来（旧格式、解密失败、平台通道不可用）时按「没有配置过」处理，页面照常打开。

存储格式是 `{version: 2, selected_id, profiles: [...]}`，单键 JSON；读到上一版的单条旧档会自动迁成一条档案（只读时迁移，下次保存才写成 v2）。

**上手仍是本地。** App 启动永远是本地助手，档案只用来让「在线」这一步不用重填；没点「在线」就不会联网。

这些都有测试守卫：`mobile_app/test/assistant_credentials_test.dart`（模型、序列化、迁移、选中）、`assistant_settings_form_test.dart`（示范、校验、隐私文案）、`assistant_api_console_test.dart`（查看/使用/编辑/删除、一键切换）。

## 六、在线回答的数字回验

在线模型最危险也最容易被忽略的失败不是答得难听，而是**编造一个不存在的次数**（「本周记录了 12 次」而摘要是 8 次）。数字可精确校验，所以 [`answer_verification.dart`](../mobile_app/lib/assistant/answer_verification.dart) 在拿到在线回答后做一次确定性回验：

- 先摘掉日期与时间串（否则「最后同步于 2026-09-23 08:00」会被误判）；
- 再只抽取**统计口径里的数字**（后面紧跟 次/条/天/日 才当计数候选，`statClaimsInText`），逐个检查是否属于「摘要有依据的数字」；
- 允许集合 = 摘要里的原始计数 + 逐日序列 + 窗口长度，**再并上规则引擎各条观察文本里的数字**——「连续 3 天」「1–5 之间波动」本来就是从摘要算出来的，模型复述它们不算编造，复用 `evaluateObservations` 即可；
- **再并上本次 RAG 检索到的那几篇知识里的数字**——「文件上限 256 个」是设备权威事实不是编造，模型照抄它不该被误判成「与摘要对不上」，所以 `verifyRemoteAnswer` 多收一个 `extra` 集合；
- 只对**在线**回答生效：本地回答就是同一份摘要算出来的，不存在编造。
- **不是所有数字都算计数。** 闲聊里的「50 岁」「8 小时」「30 分钟」「3 亿人」不是设备数据，即使数值恰好撞上摘要也不当编造——只有「次 / 条 / 天 / 日」这种统计口径才进回验。

发现对不上的数字时**只追加一句提醒，不回绝、不改写回答**。回验可能误判，静默替换掉回答比原样展示更糟；回验自身出错时直接放行，不能因为校验出问题让用户拿不到回答。

**通用知识回答跳过回验。** 见下一节：模型讲哮喘患病率时说「中国约有 3 亿人」是常识而不是摘要，拿摘要去核对只会给一句莫名其妙的「与统计摘要对不上」。所以只有标了 `【来源】记录统计` 的回答才走回验。

## 七、来源标记、聊天记录与朗读

### 7.1 提示词从「只解释摘要」改成「先回答问题」

早期的 system 提示词是「请仅解释以下统计摘要」，于是不管问什么都先念一遍统计——用户的原话是「像是人机」。现在摘要是**参考资料**：问题与记录有关才引用它，问通用健康知识（例如「介绍一下哮喘」）就直接讲，并说明这是一般科普、不能替代医生；不自我介绍、不复述能力、不每轮念摘要。禁止诊断、剂量建议和工具调用这几条**没有放宽**，也没有因为「更亲和」而变松。

副作用是回答不再天然可分：一段讲哮喘的文字完全可以和统计无关。所以提示词要求模型在**最后一行**标出来源：

```text
【来源】记录统计      ← 用了摘要
【来源】AI知识        ← 通用科普
```

[`answer_verification.dart`](../mobile_app/lib/assistant/answer_verification.dart) 的 `parseRemoteAnswer` 解析这个标记：只在**回答最末尾**匹配（容忍全角空格与全角冒号），解析后把标记行本身删掉，来源由 App 自己用界面元素表达，不给用户看方括号。没有标记、或标记出现在中间，就**原样返回、按「在线回答」处理**——绝不因为找不到标记而截断回答。

标记为 `AI知识` 时 App 在**回答最前面**补一句固定说明（浅色斜体渲染，见 7.6）：

> （以下是 AI 的通用健康知识，不是你的设备记录；涉及健康决策请以医生意见为准。）

并跳过数字回验（理由见上一节）。这样「一开头就声明信息来自 AI」是 App 保证的，不依赖模型自觉。

### 7.2 聊天记录本地保存

[`assistant_chat_store.dart`](../mobile_app/lib/assistant/assistant_chat_store.dart) 把对话存进 `shared_preferences`，单键 `assistant_chat_history`，最多保留最近 200 条，重新打开助手页时读回。

- **明文，但和设备记录同一信任级别。** 里面只有问题、回答和本地摘要片段，**没有任何凭据**——Key 与访问码仍然只在 `flutter_secure_storage`。能用 `shared_preferences` 存的东西和不能存的东西，这条线没有移动。
- **失败一律静默降级。** `load()` 出错返回空列表，`save()` / `clear()` 出错就当作这次没落盘，内存里的对话照常能用。这**与凭据 store 刻意相反**（凭据写不进去必须报错，否则用户会以为已经保存/已经删除）。区别在于代价：聊天丢一次是体验问题，凭据丢一次是隐私问题，所以两边的失败处理不能统一。
- **切换模式不再清空对话。** 以前切「本地 / 在线」会把消息整段清掉，用户提的「不能从联网模式切换一下本地就聊天全部消失」就是这条。现在只追加一条居中的分隔提示（`已启用在线助手…` / `已切回本地摘要，不联网。`，文案未变），历史一条不少。
- **每条助手回答标出来源**：`本地回答`（本地规则）、`在线回答`（在线且用了摘要）、`AI 知识`（在线且是通用科普），配不同图标与底色。用户自己的气泡不标——提问本身没有来源差异。
- **右上角「更多」→「清空对话」**（二次确认）。持久化之后必须给清除入口，否则用户没法让这些内容离开手机。

### 7.3 只有一套主题（浅色）

**App 固定浅色，没有深色模式，也没有「外观」菜单。** 曾经有过「跟随系统 / 浅色 / 深色」三态与 `AppThemeController`（落在 `shared_preferences` 的 `app.theme_mode`），已按需求移除。

- [`theme/app_theme.dart`](../mobile_app/lib/theme/app_theme.dart) 现在只有一个 `buildAppTheme()`，不再收 `Brightness`；
- 助手气泡的背景色与来源小标从「深浅两套」退回**单套**，不再按 `Brightness` 分支；
- 背景与 AppBar 仍取自 `colorScheme`，不写死 `0xfff5f7f8` 这类常量——**这一条要守住**：写死之后一换配色方案，背景就与整页脱节。

> 老用户机器上可能还留着 `app.theme_mode` 这个键。它已不再被读写，留着无害；若以后要重新引入外观切换，记得按「无存档」处理，别让旧值悄悄生效。

### 7.4 朗读（TTS）

助手回答气泡右下角有「朗读」按钮，走手机的 Android 系统 TTS（[`assistant_tts.dart`](../mobile_app/lib/assistant/assistant_tts.dart)，`flutter_tts` 插件）。**能否离线取决于手机安装的语音引擎和中文语音包**；部分系统语音需要联网，因此不能保证朗读文本始终留在手机。朗读不使用助手的 API Key，也不经过团队网关。Android Manifest 已声明 `TTS_SERVICE` 查询，以支持 Android 11 以上的语音服务识别。

设备没装 TTS 引擎、没有中文语音包、引擎拒绝请求或无响应时，点「朗读」会恢复按钮并弹出固定提示「此设备暂不支持朗读。」，不回显底层错误。初始化与停止调用最多等待 8 秒；朗读结束回调另有按文字长度和语速计算的超时兜底。用户自己的提问不提供朗读按钮——只读助手回答。

**朗读是一个开关，不是单向动作。** 正在读的那条回答会把「朗读」变成「停止」，再点一次就停；读完（或被停、或引擎报错）自动收回成「朗读」。这件事比看起来微妙：`FlutterTts.speak` 在 Android 上是**立刻返回**的，不能当「读完」信号，所以 [`assistant_tts.dart`](../mobile_app/lib/assistant/assistant_tts.dart) 把引擎的完成/取消/出错三种回报翻译成一个 Future，`speak` 在读完时才完成；界面靠它还状态。同时用代号（generation）作废掉迟到的回调，否则上一段的进度会盖到刚开的那一段上。

**读出进度用小字表示，不动正文本身。** 引擎按「已读到第几个字符」回报（Android 26+ 与 iOS 的 speech marks 支持，见 `setProgressHandler`），未读到的部分渲染成灰色、已读的保持原样式。只改渲染、不改文本，所以搜索、落盘、重试用的仍是原文。引擎不支持进度回报时这个回调不会来，界面就只是没有灰色高亮——朗读本身不受影响。未读部分保留该段的字重与斜体，只有颜色变灰，因此「这段是数字还是提醒」不会因为还没读到而看不出来。

「更多」→「朗读设置」补全朗读体验，三项都落在 [`assistant_settings.dart`](../mobile_app/lib/assistant/assistant_settings.dart) 的 `shared_preferences` 偏好里（与聊天记录同为“便利”类偏好，写失败静默降级，不碰凭据）：

- **回答后自动朗读**（默认关）：开启后新回答自动读出来；
- **语速 / 音调滑杆**：0–1 / 0.5–2，对应 flutter_tts 的 `setSpeechRate` / `setPitch`；
- **只读最新一句**：每次朗读前先 `stop()`，新问题开始也先停掉上一段，同一时刻只有一段语音，旧回答不会盖过新回答。

### 7.5 流式回答与多轮上下文（仅直连）

「我自己的模型」直连（`DirectLlmAssistantProvider`）支持 OpenAI 兼容的 `"stream": true` SSE 增量输出：回答边出边显示，而不是等满 55 秒整段返回。服务端若不支持流式、直接回了整段 JSON，会自动兜底成单次回答；所有失败分支照旧只说固定文案、不回显 Key 或响应体（有测试守卫）。

**多轮上下文默认关。** 「更多」→「带上本轮对话」开启后，只有直连自己的模型时，才把本轮更早的问答作为 chat message 插在 system 与当前问题之间，帮助理解追问；仍不发送原始记录、设备标识，也不会把历史发给团队服务器（网关已废弃、本来就不支持多轮）。开关状态和朗读偏好一起存在 `shared_preferences`，隐私横幅与切到在线的分隔提示会随开关如实说明“到底发出去什么”。

**发送前按相关性裁剪，而不是“一律带最近 8 条”。** [`history_relevance.dart`](../mobile_app/lib/assistant/history_relevance.dart) 的 `relevantTurns` 决定带哪些历史：不超过 8 条时原样带上、顺序不变；超过时**始终保留最近一回合**（“还有呢”这种零重叠追问才不会断），再带上与当前问题共享字符二元组的早期问答，合计最多 8 条。这样既不会因为无关历史把整段聊天都发出去（省 token、也少泄露），也不会丢掉真正相关的上文。

多轮说明是一段**独立常量** `assistantHistoryNote`，只在请求时拼到 system 提示词之后，**不并入** `assistantSystemPrompt`——因为那份要与 `gateway.py` 的 `SYSTEM_PROMPT` 逐字同步，而网关不支持多轮；拼进去会破坏 `test_prompt_sync.py` 的逐字比对。

### 7.6 回答强调、反馈、追问建议、搜索、同步徽标、大字模式、取消与重试

助手页还有几个纯界面的辅助功能，全部**不改动存储或发送的原文，也不碰凭据边界**：

- **回答强调（只改显示、不动原文）**：[`answer_styling.dart`](../mobile_app/lib/assistant/answer_styling.dart) 在**渲染时**把一条回答拆成带样式的片段——开头的「声明」（通用知识「不是你的设备记录」那句）浅色斜体、正文黑色、摘要里有依据且后接「次 / 条」的个人计数蓝色、回验提醒或本地「需要留意」红色加粗。它只决定哪段字是什么颜色，朗读、搜索、落盘仍用原始字符串，所以不会丢信息；通用知识回答（`ChatSource.knowledge`）不传个人数字集合，因此「全球约 3 亿人」这类常识数字不会被误标成用户数据；普通回答里也只有数值命中摘要**且**紧跟「次 / 条」时才标蓝，「50 岁」「3 亿人」这类闲聊数字一律不标。
- **接着问（追问建议）**：[`follow_up_suggestions.dart`](../mobile_app/lib/assistant/follow_up_suggestions.dart) 按**用户问句**（而不是在线模型的自由文本回答）路由到同主题的快捷问题，本地/在线两种模式共用；只落在「本地可答」的主题集内，不诱导医疗判断。
- **离线搜索**：右上角搜索按钮按关键字筛历史对话，只读本地 `shared_preferences` 里的聊天记录，不发任何网络请求。
- **同步状态徽标**：[`sync_status.dart`](../mobile_app/lib/assistant/sync_status.dart) 按设备记录的同步时间分三类——`尚未同步` / `数据可能不是最新`（至少三个日历天未同步，口径同规则层 `syncStaleAfterDays = 3`）/ `已同步`，只陈述数据新旧，不说设备好坏。0.3.2 已移除演示数据功能，所有摘要只来自设备记录；JSON 中的历史兼容字段 `is_demo` 固定为 `false`。
- **大字模式**：「更多」→「大字模式」把整页文字放大（约 1.25×，钳制在 1.0–2.2），偏好落在 [`assistant_settings.dart`](../mobile_app/lib/assistant/assistant_settings.dart) 的 `shared_preferences`（与朗读偏好同类，写失败静默降级）。
- **逐日柱状图**：摘要卡片把近 7 天逐日次数画成小柱状图，点任一天可看当天次数；今天高亮、空档用轮廓色区分。
- **回答质量反馈（赞 / 踩）**：每条助手回答右下角有「有帮助 / 没帮助」。赞只做标记；踩在线/知识回答时**不回传模型、也不落盘**，而是用本地规则把同一问题重新解释一遍作对比——反馈只影响本地界面，绝不把反馈发给模型（有测试守卫）。
- **失败重试**：回答失败（超时、解析失败等）会显示一条「上次回答失败，点这里重试」，重新发送同一条问题；失败气泡只说固定文案、不回显 Key 或响应体。失败气泡还会被标成 `ChatMessage.isError`，**多轮上下文里会被滤掉**：那是 App 写的提示、不是模型说过的话，回灌过去会让模型把自己上一条「模型服务响应超时」当成已经答过的内容。
- **取消 / 停止**：等待回答或流式输出中，可点「取消」/「停止」立即回到可输入状态，**并且真的掐断底层请求**。两件事缺一不可：代次计数让迟到的结果被丢弃；取消 `StreamSubscription` 让 `DirectLlmAssistantProvider` 的 `onCancel` 关掉 `HttpClient`，模型那边才会停下来——只作废结果的话，请求还在跑、token 还在烧。「清空对话」和离开页面走同一条路。
- **回答没确认收完**：流式回答若在收到 `data: [DONE]` 之前就断了，**不丢已收到的文字**（有些兼容服务端本来就不发哨兵，内容往往是完整的），而是在末尾补一句「这次回答没有收到结束标记，可能不完整，请核对后再采用」。判断走 `StreamCompletion`（`assistant_provider.dart`），由 provider 填写、页面读取；真正连不上的错误仍照旧报错重试。

## 八、必须守住的事

- **API Key 只能是用户自己的，加密保存在手机，调用时直接发送给所选模型服务、不经过团队服务器。** 团队/共享 Key、以及“用户 Key 经过团队服务器”的网关透传路线已废弃；任何新代码都不得再引入服务端持有 Key 的路径。Key 只允许写入 `flutter_secure_storage`；**绝不进源码、构建参数、日志或 `shared_preferences`**。
- 只允许 HTTPS；仅 debug 版允许本机 HTTP 联调。地址不允许带用户名密码、查询参数或片段；`/chat/completions` 会自动补齐且只补一次。
- **所有失败分支只说固定文案**，绝不回显 Key 或上游响应体 —— 有测试守卫（`mobile_app/test/direct_llm_assistant_test.dart`）。
- 不要在 Wiki、截图、issue、演示视频里出现真实 Key。
- 提示词禁止诊断与剂量建议。这段文本在 App（`mobile_app/lib/assistant/assistant_prompt.dart`）和网关（`gateway.py` 的 `SYSTEM_PROMPT`）**各有一份**——BYOK 直连路径不经过网关，所以 App 这份必须自己带着完整约束。两处必须逐字一致，由 `server/assistant-gateway/tests/test_prompt_sync.py` 在 CI 里强制：它直接读 Dart 源码抽取字符串与 `SYSTEM_PROMPT` 比对，改一处不改另一处会直接失败。（该测试还要求提示词保持单行、正文不含单引号与分号，改提示词时按这个格式写。）
- **「更亲和」不是放宽边界。** 允许回答通用健康知识之后，这段提示词仍然保留 `不要诊断`、`推荐剂量`、`不证明实际服药` 三条硬约束，`test_prompt_sync.py` 会检查它们还在。通用科普回答由 App 补上「不是你的设备记录」，不靠模型自觉。
- 用用户自己的 Key **不等于**可以跳过“每次提问前告知要发送什么”—— 同意开关仍然保留。
- 在线回答同样受安全边界约束：设备动作次数不代表确认服药，不给剂量建议，不修改记录。
- **RAG 语料不放医学内容**：设备边界、错误码、时间/同步、维护、隐私、术语可以进；药品说明书、剂量表、用药指导、疾病说明一律不进（见 `server/assistant-gateway/knowledge/README.md`）。通用健康问答由模型知识 + `【来源】AI知识` 标记处理。
